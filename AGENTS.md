# Agent context — reproducible-r-workflow-demo

This file provides context for a large language model assisting with this repository.

## What this repository is

This repository is a worked example of a reproducible R analysis workflow, built
around the [Palmer penguins](https://allisonhorst.github.io/palmerpenguins/)
dataset. It accompanies a live presentation teaching `targets`, `renv`, and
GitHub Actions to a mixed audience of data scientists.

The core message of the project:

> Reproducibility is not one tool. It is a workflow: scripted analysis, recorded
> dependencies, version-controlled project structure, automated checks, and clear
> documentation.

## The targets pipeline

The pipeline is defined in `_targets.R` and uses `tar_source("R/")` to load all
functions from `R/`. The dependency graph is:

```
raw_penguins
    ↓
clean_penguins
    ├── species_summary
    ├── island_summary
    ├── body_mass_plot
    └── body_mass_model
              ↓
         model_summary
              ↓ (all outputs feed into)
           report
```

| Target | Function | Description |
|:-------|:---------|:------------|
| `raw_penguins` | `get_penguins()` | Loads `palmerpenguins::penguins` |
| `clean_penguins` | `clean_penguins_data()` | Removes rows missing `body_mass_g` or `sex` |
| `species_summary` | `summarize_by_species()` | Mean and SD body mass by species |
| `island_summary` | `summarize_by_island()` | Mean and SD body mass by island |
| `body_mass_plot` | `plot_body_mass()` | Boxplot of body mass by species and island |
| `body_mass_model` | `fit_body_mass_model()` | `lm(body_mass_g ~ species + island + sex)` |
| `model_summary` | `extract_model_summary()` | `broom::tidy()` of the model |
| `report` | `tar_quarto()` | Renders `reports/penguins_report.qmd` |

To run the pipeline: `targets::tar_make()`
To inspect the graph: `targets::tar_visnetwork()`
To check what is outdated: `targets::tar_outdated()`

## Key conventions

- **Functions, not scripts.** Analysis logic lives in small, single-purpose functions
  in `R/`. Functions are loaded by `tar_source("R/")` in `_targets.R`. There are no
  numbered scripts (e.g. `01_clean.R`). Instead, the pipeline order is dictated
  by the `_targets.R` pipeline.

- **Fully qualified calls.** Prefer `dplyr::filter()` over `library(dplyr); filter()`.
  `tar_option_set(packages = ...)` declares which packages targets will attach when
  running the pipeline; this is the only place where implicit package loading is
  configured.

- **No `library()` in `R/` functions.** Functions in `R/` use fully qualified calls.
  The exception is `_targets.R` itself, which calls `library(targets)` and
  `library(tarchetypes)`.

- **Reports consume pipeline outputs, not the other way around.** `penguins_report.qmd`
  loads targets with `targets::tar_load()` and does not repeat analysis inline.

- **`renv.lock` is the environment record.** Commit it. Do not commit `renv/library/`.

- **Keep examples small.** The statistical model (`lm`) is intentionally simple.
  The goal of this repository is workflow structure, not modelling sophistication.

## What to be careful about

- Do not change the model formula without a deliberate reason — it is part of the
  teaching example, not a research-grade modelling choice.
- Do not add `library()` calls to files in `R/`.
- Do not add executable analysis code to `reports/penguins_report.qmd` beyond what
  is needed to load and display pipeline outputs.
- The slide deck (`slides/reproducible_r_workflows.qmd`) uses `eval: false` —
  code blocks are illustration only and are not executed during rendering.
- `outputs/` files are derived products; they can be regenerated and should not be
  hand-edited.
